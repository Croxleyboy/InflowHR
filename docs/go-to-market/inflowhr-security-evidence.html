4. Security migration trail

Every security fix is applied through a numbered, version-controlled SQL migration. These migrations form the auditable change history for database-level security controls.

  • 026_lock_down_anon_policies.sql Replace anon USING(true) with company-scoped RLS
  • 034_block_anon_access.sql Block all anon access to tenant data
  • 035_rls_unprotected_tables.sql Enable RLS on tables missing it
  • 047_gdpr_compliance.sql Consent-based access, audit logging, export, anonymisation
  • 049_refine_gdpr_access.sql Tiered super-admin access; PII gated by support grant
  • 055_critical_security_fixes.sql Guard delete_company_data, promote_to_admin, e-learning
  • 056_high_security_fixes.sql Guard run_demo_seed; role-based write RLS on employees
  • 057_medium_security_fixes.sql Fix admin escalation via email; add audit + retention cron
  • 063_low_security_fixes.sql Lock down user_settings to authenticated own-row-only
  • 070_fix_gdpr_audit_action_check.sql Add SELF_GRANT_ACCESS to audit constraint
  • 073_asset_gdpr_rls.sql GDPR consent-gated RLS on company_assets
  • 093_security_audit_fixes.sql Fix cross-tenant leaks, admin_portal RLS, super_admins table
  • 094_smb_readiness.sql Salary RLS isolation, storage policies, temp password cleanup
  • 097_security_audit_v2.sql Drop stale USING(true) policies from migration 001
  • 098_fix_cron_purge_auth.sql Allow postgres role to bypass is_super_admin() for pg_cron
  • 099_fix_anonymise_columns.sql Fix wrong column names in anonymise_employee
  • 100_fix_audit_constraint_and_export.sql Add AUTO_PURGE to constraint; fix export column
  • 101_fix_export_anonymise_role_guard.sql Role guards on export (self/admin) and anonymise (admin)
  • 102_scan_fixes.sql Remove hardcoded email; REVOKE from anon; drop permissive policy
