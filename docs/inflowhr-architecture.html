Hosting & Deployment

The app is a single-page application deployed to Cloudflare Pages. The deployment pipeline is: commit to dev branch → push → PR to main → merge → Cloudflare auto-deploys.

Security Headers (Cloudflare _headers)

  • Content-Security-Policy — default-src 'self'; scripts and styles allow 'unsafe-inline'; images allow Supabase and OpenStreetMap tiles; connections restricted to Supabase endpoints
  • X-Frame-Options: DENY — prevents clickjacking
  • X-Content-Type-Options: nosniff
  • Referrer-Policy: strict-origin-when-cross-origin
  • Permissions-Policy — camera/microphone denied, geolocation self-only, payment denied

Session Management

  • AuthProvider calls getSession() on mount and subscribes to onAuthStateChange()
  • On session detected: calls ensure_company_user() RPC to link/create the company_users record
  • Resolves employee_id by exact email match, then fuzzy local-part match
  • Checks login_disabled flag and trial expiry on the company
  • Inactivity timeout: 15 minutes. Monitors mouse, keyboard, scroll, touch. Cross-tab check every 30s via sessionStorage.

Multi-Tenancy Model

Every data table carries a company_id column (UUID FK to companies). Tenant isolation is enforced through:

  • Row Level Security (RLS) on every table, using is_my_company(company_id) to verify the current user belongs to the company
  • A BEFORE INSERT trigger (auto_set_company_id) on 13 core tables that stamps company_id from get_my_company_id()
  • Super admin access is gated through can_access_company() which requires an active tenant_support_access grant (GDPR consent-based)

Row Level Security

RLS Architecture

Three tiers of access control using helper functions:

FunctionLogic
is_my_company(uuid)Current user has a company_users row for this company. SECURITY DEFINER.
is_super_admin()Current user's email matches hardcoded super admin emails. SECURITY DEFINER.
can_access_company(uuid)For regular users: is_my_company(). For super admins: requires has_active_support_access() (GDPR consent grant).
is_company_admin()Current user has admin or hr role in company_users.

Policy Tiers

  • Tier 1 — PII tables: can_access_company(company_id) only. Super admin must have consent grant. Covers: employees, expenses, leave, payslips, onboarding, timesheets, etc.
  • Tier 2 — Config tables: can_access_company(company_id) OR is_super_admin(). Super admin can always read config. Covers: leave_types, benefits, spaces, courses, etc.
  • Tier 3 — Write-restricted: Additional role checks (admin/hr) for INSERT/UPDATE/DELETE on: work_locations, checkin_settings, labour_demand, admin_portal_roles.

Security Audit — Critical

SEC-C01: admin_portal_roles / admin_portal_access — Cross-Tenant Data Leak

Tables: admin_portal_roles, admin_portal_access (migration 087)
Issue: RLS policies use TO authenticated USING (true) for ALL operations. Any authenticated user from any company can read, insert, update, and delete role definitions and access grants for all companies.
Impact: Cross-tenant privilege escalation. An employee at Company A could grant themselves admin portal access at Company B.
Fix: Replace USING (true) with USING (is_my_company(company_id)) for SELECT, and add admin/hr role check for writes.

SEC-C02: send-notification-email Edge Function — No Authentication

File: supabase/functions/send-notification-email/index.ts
Issue: No auth header validation. Anyone who knows the function URL can trigger email sends via the Brevo API.
Impact: Email spoofing from the InflowHR domain, quota exhaustion, potential spam abuse.
Fix: Add Bearer token validation and verify the caller is authenticated. Consider also checking that the notification record exists and belongs to the caller's company.

SEC-C03: app_translations — Anonymous Full CRUD

Table: app_translations (migration 011)
Issue: Retains FOR ALL TO anon USING (true). Anonymous users can INSERT/UPDATE/DELETE translation strings without any authentication.
Impact: Content injection. An attacker could modify UI text to display phishing messages, offensive content, or misleading instructions.
Fix: Drop the anon policy. Add TO authenticated USING (true) for SELECT and admin-only for writes.

Security Audit — High

SEC-H01: Receipts Storage Bucket — Public Access + Unscoped Delete

Issue: The receipts bucket is set to public = true, meaning receipt file URLs are accessible without authentication. The DELETE policy also has no company scoping — any authenticated user can delete any company's receipts.
Fix: Set the bucket to private. Add company-scoped folder structure (e.g., {company_id}/{claim_id}/receipt.pdf) and scope storage policies to the user's company.

SEC-H02: is_super_admin() Hardcodes Email Addresses

Function: is_super_admin() checks auth.jwt() ->> 'email' against two hardcoded emails.
Issue: If either account is compromised or deprovisioned, there is no recovery path without deploying a migration. Adding/removing super admins requires a database migration.
Fix: Create a super_admins table with email addresses. The function checks against this table instead. Manage via protected admin UI.

SEC-H03: delete_company_data Temporarily Disables RLS

Function: delete_company_data(uuid)
Issue: Runs ALTER TABLE ... DISABLE ROW LEVEL SECURITY on one_to_one_comments and one_to_one_meetings during execution. If the function errors mid-execution, RLS remains disabled, exposing these tables to all authenticated users.
Fix: Use SECURITY DEFINER context to bypass RLS instead of disabling it, or wrap the disable/enable in an exception handler.

SEC-H04: CORS Wildcard on All Edge Functions

Issue: All edge functions set Access-Control-Allow-Origin: *. This allows any origin to call these functions.
Fix: Restrict to the production domain (https://app.inflowhr.com) and any staging domains.

SEC-H05: xero-callback State Parameter Not Signed

Function: xero-callback
Issue: The state parameter is base64-encoded JSON containing company_id but is not signed or validated against a server-side nonce. An attacker could craft a state value to associate a rogue Xero connection with a target company.
Fix: Generate a random nonce, store it server-side (or sign it with HMAC), and verify it on callback.

SEC-H06: HTML Injection in Edge Function Email Templates

Functions: send-notification-email, daily-email-reminders
Issue: firstName, title, and message are interpolated directly into HTML email templates without escaping. If notification content contains user-controlled markup, it enables stored XSS/HTML injection in emails.
Fix: HTML-escape all dynamic values before interpolation.

Security Audit — Medium

SEC-M01: Feature Flags Don't Block Routes

Feature flags control UI visibility but not route access. A user at a company without the timesheets add-on can navigate directly to /timesheets. Security depends entirely on backend RLS preventing data access, which works correctly, but the page component still renders (possibly with empty state).

SEC-M02: Approval Routes Lack Role Guard

/approve/expense/:id, /approve/leave/:id, and /approve/timesheet/:id are accessible to any authenticated employee. The components check manager status internally, but there is no route-level guard. A non-manager visiting the URL sees the request details before the component-level check redirects them.

SEC-M03: Portal Role Grants Full Admin Access

Any employee with an admin_portal_access record passes the AdminGate for all admin routes, not just specific sections. There is no per-route portal role scoping. The permissions JSONB column on admin_portal_roles exists but is not checked by the frontend.

SEC-M04: Console.log Leaking PII

src/lib/supabase.ts lines 34 and 44 log notification payloads (employee names, emails, notification content) and response bodies to the browser console. Should be removed for production.

SEC-M05: Super Admin Emails in Client Bundle

VITE_SUPER_ADMIN_EMAIL and VITE_BREAK_GLASS_EMAIL are VITE_-prefixed, meaning they are embedded in the production JavaScript bundle. Anyone inspecting the built JS can identify the super admin email addresses.

SEC-M06: Break-Glass Domain Typo

VITE_BREAK_GLASS_EMAIL is set to breakglass@kumonic.com (missing the "x" — should be kumonix.com). If this domain is unregistered, an attacker could register it and receive break-glass login credentials.

SEC-M07: Dashboard-Created Tables Not Version-Controlled

~15 tables were created via the Supabase dashboard UI. Their schemas exist only in the live database, not in migration files. If the database needs to be recreated, these tables would be missing.

Security Audit — Low / Informational

SEC-L01: unsafe-inline in CSP script-src

The CSP allows 'unsafe-inline' for scripts. This weakens XSS protection, though it's common for SPAs that use inline event handlers. Consider nonce-based CSP if feasible.

SEC-L02: dangerouslySetInnerHTML Usage

AdminLayout.tsx:119 uses dangerouslySetInnerHTML to render SVG icon markup. The values are static nav icon strings defined in code, so the actual risk is low. Document this as an accepted risk.

SEC-L03: expire_stale_support_grants Not Scheduled

The function exists but no pg_cron schedule is defined. Expired grants functionally expire (the access check also verifies expires_at > now()), but their status column remains "active" in the database, which is misleading for audit queries.

SEC-L04: email_notification_settings Uses get_my_company_id()

This function returns the first company for multi-company users, which may be the wrong one. Should use is_my_company() for accuracy.

SEC-L05: Hardcoded Domains in Source

Several source files hardcode inflowhr.com, inflowhr.co.uk, kumonix.com etc. for billing invoices, email templates, and fallback URLs. These should be env vars or config for portability.

Bundle & Performance

No Code Splitting

All 70+ page components are eagerly imported at the top of App.tsx. Zero use of React.lazy() or Suspense. The entire application (45,000+ lines of TSX) ships as a single JavaScript bundle. Admin pages (which most users never visit) bloat the initial payload for regular employees.

Recommendations

  • Lazy-load the admin route tree: const AdminDashboard = React.lazy(() => import('./pages/admin/AdminDashboard')). This alone would significantly reduce the initial bundle for employees.
  • Dynamic import xlsx: The xlsx library (~300 KB) is imported at the top of AdminOnboarding.tsx. Use const XLSX = await import('xlsx') only when the export button is clicked.
  • Add Vite manual chunks: Split heavy libraries (xlsx, jspdf, jszip, leaflet) into separate chunks via build.rollupOptions.output.manualChunks.
  • Single CSS file: All 6,700 lines of CSS are in one index.css. Consider CSS modules or splitting by feature area for better caching.

Troubleshooting: Auth Issues

"Access Denied" after login

  1. Check company_users for a row matching the user's auth_user_id. If missing, the ensure_company_user() RPC may have failed.
  2. For SSO users: verify the Microsoft tenant ID matches the companies.microsoft_tenant_id. A mismatch means the trigger handle_new_sso_user() created a new company instead of linking to the existing one.
  3. Check companies.login_disabled — if true, all users are locked out.
  4. For trial companies: check is_trial, trial_end_date. Expired trials block access.

Employee not linked to company_users

ensure_company_user() matches by: (1) exact email, then (2) local-part fuzzy match (e.g., john.smith@company.com matches john.smith@otherdomain.com). If neither matches, the employee won't be linked. Fix: manually set company_users.employee_id to the correct employee UUID.

Super admin can't see company data

Since GDPR compliance (migration 047), super admins need an active tenant_support_access grant to access company data. Go to Admin → Subscriptions → Support Access tab and grant access, or run ensure_super_admin_access() RPC.

Break-glass login fails

Verify: (1) VITE_BREAK_GLASS_EMAIL domain is correct (currently kumonic.com, should be kumonix.com?). (2) The break-glass account exists in auth.users. (3) The password is correct — there's no password reset UI for break-glass.

Troubleshooting: Data & RLS

Query returns empty when data exists

  1. RLS is blocking. Check the user has a company_users row with is_active = true for the target company.
  2. For super admins: ensure tenant_support_access exists and hasn't expired.
  3. For dashboard-created tables: confirm RLS is enabled (ALTER TABLE ... ENABLE ROW LEVEL SECURITY) and policies exist.

Data visible across companies

Check the table has: (1) company_id column populated, (2) RLS enabled, (3) policies using is_my_company(company_id) or can_access_company(company_id). The admin_portal tables (migration 087) are a known gap — see SEC-C01.

Workflow notifications not appearing

The workflow_tracker table is the backbone of the notification system. Check: (1) assigned_to matches the employee's email, (2) status is not already 'Complete', (3) company_id is correct. The employee Notifications page queries workflow_tracker where assigned_to = current user's email.

Leave balance not updating after approval

The LeaveApproval component updates leave_balances.used directly in the frontend after approval. Check: (1) leave_balances row exists for the employee/year/leave_type, (2) the leave type has deducts_from_allowance !== false. Non-deducting types (e.g., jury duty) skip the balance update.

Troubleshooting: Email Notifications

Emails not sending

  1. Check company_features for email_notifications — must be is_enabled = true.
  2. Check email_notification_settings for the specific feature toggle (e.g., leave_enabled).
  3. Check the notifications table for send_email = true and email_sent = false.
  4. Check Edge Function logs: supabase functions logs send-notification-email.
  5. Verify BREVO_API_KEY is set in Supabase Edge Function secrets.

Daily reminders not firing

The daily-email-reminders function must be called by a scheduled trigger (Supabase cron or external). Check the Supabase dashboard under Database → Extensions → pg_net / cron, or Edge Function Schedules.

Troubleshooting: Xero Integration

Xero connection failing

  1. Verify Edge Function secrets: XERO_CLIENT_ID, XERO_CLIENT_SECRET, XERO_REDIRECT_URI.
  2. Check xero_integrations table for the company — is there an existing row with expired tokens?
  3. The callback function upserts tokens, so a reconnect should overwrite stale credentials.
  4. Check that the redirect URI in Xero's developer portal matches XERO_REDIRECT_URI exactly.

Payslip sync returning wrong data

The xero-payslips function matches employees by email. If an employee's Xero email doesn't match their InflowHR email, the payslip won't link. Check the email mapping in the sync logs.

Troubleshooting: Check-In / Geolocation

Check-in button not appearing

  1. Check checkin_settings for the company — timesheets_checkin_enabled or shifts_checkin_enabled must be true.
  2. If allowed_departments is set, the employee must be in one of those departments.
  3. The CheckInContext loads settings on mount and exposes isEnabled.

Location verification failing

The matchLocation() function in lib/geolocation.ts uses haversine distance to compare the employee's GPS coordinates against work_locations entries. Check: (1) work_locations has correct lat/lng for the office, (2) radius_metres is large enough (GPS accuracy varies), (3) allow_remote is set if WFH should be allowed.

Auto-checkout not working

The auto_checkout_hours setting in checkin_settings defines when open check-ins are automatically closed. This must be handled by a scheduled process (pg_cron or Edge Function cron). If no schedule is configured, check-ins will remain open indefinitely.
